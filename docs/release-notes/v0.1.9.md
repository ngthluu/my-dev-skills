# 0.1.9

## Features

- Brainstorm now keeps a session folder at `.my-dev-skills/<slug>/` holding `context.md`, a decision ledger (`ledger.json`), optional visuals, an optional review, and the handoff spec (`README.md`). The ledger is managed by a bundled script, `scripts/ledger.mjs`. The script rejects status changes that lack required evidence, picks the next question, and fails its audit while material decisions remain open, blocked, or contradicted.

## Improvements

- The brainstorm handoff spec now follows a fixed template: goal, current state, what to build, decisions, out of scope, where to change, acceptance criteria with public test seams, suggested slices, verification commands, and constraints and risks. Brainstorm replies with only the spec path.
- Brainstorm runs a throwaway experiment for a question one can settle. It asks the user only about preferences and priorities.
- Implement starts from a spec's suggested slices, confirms its "Where to change" paths, and runs its verification commands. It favors minimal code: it reuses existing helpers, deletes replaced paths, and adds no speculative abstractions or compatibility shims. It also reviews the whole diff for removable code before review.
- Debug fixes a fault where it starts rather than where it shows, reverts edits made for refuted hypotheses, and ships no "might help" changes beside the fix. Its code review now flags guards that hide illegitimate states.

## Upgrade notes

- Brainstorm no longer writes specs to `docs/specs/yyyy-mm-dd-<slug>.md`. The spec is now a temporary handoff at `.my-dev-skills/<slug>/README.md`. The folder ignores itself through `.my-dev-skills/.gitignore`, so nothing is committed. To keep a spec, copy it elsewhere. Pass the new path to implement, for example `Use the implement skill with .my-dev-skills/activity-log/README.md.`
- The brainstorm ledger script runs with `node`, so Node.js must be available where the agent runs.
